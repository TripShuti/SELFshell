# Contributing

## Мова
- Код, коментарі, документація, коміти — **українською**
- UI-рядки (те, що бачить користувач) англійською
- Назви змінних, функцій, компонентів — англійською (мовою програмування)

## Стиль коду
- Кожен файл у проєкті має починатися з банера:
  ```
  // ============================================================
  // <шлях>/<ім'я> — короткий опис одним реченням
  // ============================================================
  ```
  Коментар у форматі, відповідному мові файлу (`#`, `//`, `--`).
- Для допоміжних файлів (дані, проста конфігурація) — коротший однорядковий коментар

## Коли писати коментар
- Рішення неочевидне з коду (архітектурний вибір, обхід бага, компроміс)
- Є відомий workaround довкола бага фреймворка
- Формат даних не самоочевидний
- Є відома крихкість/edge case, який свідомо не вирішувався

Не писати коментар, який просто повторює назву змінної/функції — це шум.

## Коміти
- Один коміт за сесію (якщо не вказано інакше)
- Префікси: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`
- Якщо змінюєш логіку — онови коментар поруч у тому самому коміті

## Валідація
- Bash-скрипти (`install.sh`, `scripts/selfshell`, `update-palette.sh`):
  `bash -n <файл>`
- `hypr/modules/json.lua` + `env.lua`/`exec.lua`/`general.lua`:
  `luac -p hypr/modules/*.lua` для синтаксису + юніт-тест через luajit
  (мок глобального `hl`, `package.path` на `hypr/`; json.lua має
  повертати `nil` на будь-який пошкоджений вхід)
- QML: `quickshell` не має `--check` — `selfshell reload` та перевірка
  логів `qs log` на "Configuration Loaded"
- Після зміни hypr-конфігів: `hyprctl reload` + `selfshell doctor`
